# 外部BGM

音楽ファイルは各自で用意してください。音楽なしでも従来どおり遊べます。
設定メニューの「BGM設定...」でXMLを選択すると読み込み、現在の場面に合った曲を再生します。
BGMのオン／オフと音量を調整できます。既存の「サウンド」は効果音のオン／オフです。
効果音の音量は同じ設定画面の別のスライダーで調整します。
設定内容と音量は次回起動時にも引き継ぎます。XMLの編集後は「再読み込み」を押してください。

初回から設定を指定する場合:

```sh
java -Dmicropolis.music=/path/to/music.xml -jar target/micropolis-2.0.0.jar
```

例は [examples/music.xml](../examples/music.xml) を参照してください。
相対パスはXMLファイルのフォルダを基点とします。日本語のファイル名も利用できます。
個人用の音楽パックはGit管理外の `private/music/` などに配置してください。

## 設定

- `music.volume`: パック全体の基準音量（0〜1）。設定画面の音量をさらに掛けます。
- `fadeMillis`: 曲を切り替える際のフェード時間（0〜10000ミリ秒）。順番にフェードアウト／インします。
- `pauseWithGame`: `true` ならシミュレーションの一時停止中にBGMも一時停止します。既定は `false`。
- `track`: 一意の `id` と `file`。`loop` は既定で `true`。
- `track.seconds`: 1回の再生を区切る秒数。0または省略ならファイル終端まで（SPCは180秒）。途中からのループは未対応です。
- `rule.scene`: `title`（起動・新規都市選択中）、`city`（都市プレイ中）、`disaster`（災害通知）、`reward`（人口到達の通知）、`evaluation_good`／`evaluation_bad`（都市評価画面）。
- `rule.cityClass`: 都市ルールだけに指定できます。0〜5が村・町・都市・首都・大都市・巨大都市。省略なら全段階。
- `rule.priority`: 同じ場面のルールで数値が大きいものを優先。同じ値なら都市クラス指定ありを優先し、それも同じなら先に記述したルール。
- `rule.seconds`: 災害・人口到達の割り込み時間。既定15秒（0.1〜3600秒）。通常曲・表示中の評価曲より優先度が低ければ割り込みません。評価曲の表示期間には使いません。

災害曲は実際の災害の存続時間と連動しません。指定時間後、表示状態に応じた評価曲または都市クラスの曲へ戻ります。
同じ種類の追加通知では曲を頭から再生せず、時間も延長しません。
異なる割り込み曲は、現在の割り込みより優先度が高い場合だけ切り替わります。
サンプルでは災害100、人口到達50、評価10、通常0の順です。低い優先度の通知は予約せずに見送ります。
都市評価の更新時と都市の読み込み時に選曲し直します。同じ曲なら再生位置を維持します。
ゲーム速度を変えても再生速度は変わりません。

都市評価画面を開いている間は、市長への支持率が50%以上なら `evaluation_good`、
50%未満なら `evaluation_bad` を選びます。総合得点とは別の指標です。
支持率の変化に追従し、評価画面を閉じると通常曲へ戻ります。
評価中に災害などの割り込みがあった場合、時間切れ後はその時点の表示状態・支持率に従って選曲します。
評価画面を閉じた後に割り込みが終われば、現在の都市クラスの曲へ戻ります。

`reward` は人口2千・1万・5万・10万・50万への到達通知で再生します。
プレゼント施設の追加ではなく、既存の都市発展通知への音楽演出です。
これらの場面を定義していない既存XMLは変更不要です。評価曲が未定義なら通常曲を維持し、
人口到達の曲が未定義なら割り込みません。

## 形式と配布構成

対応目標はPCM WAV、MP3、Ogg Vorbis、FLACです。Ogg Opusや多チャンネル音声は対象外です。
一般音声は8〜192 kHz、モノラル／ステレオを扱います。
Oggは単一論理ストリームに対応し、連結されたOggは対象外です。
SPCはGame Music Emu 0.6.5を使い、44.1 kHz・16ビット・ステレオで再生します。
ROMを読み込む機能やROMからの取り出し器はゲーム本体に含みません。
手元専用の取り出し器では、タイトル、都市6段階、災害、評価の良否、人口到達、贈呈などの
音楽の対応付けを確認しています。具体的な取り出し手順・入力データは公開側に含みません。
公開側は生成済み音源と通常のXMLだけを読み込みます。
SPCは同じ `track.file` に `.spc` を指定します。タグの再生時間やループ位置は使わず、
`track.seconds` で区切りを指定します。省略または0の場合、SPCだけは180秒で区切ります。
ループ有効なら先頭のスナップショットから再開します。内蔵ドライバによる曲中のループとは別の設定です。

Windows x64ではJava 25、CMake、Visual Studio 2022のC++ビルドツールを用意し、次の順序で作成します。

```powershell
mvn clean
./scripts/build-spc.ps1
mvn package
./start-micropolis.ps1
```

SPCのビルド後に `mvn clean` を挟むとネイティブライブラリも削除されます。
スクリプトは固定リビジョンのlibgmeを取得し、SPC専用DLLと対応ソースを配布ZIPに含めます。
対応ソースにはエミュレーターのコードを保持し、未使用の付属テスト音源は除外します。
通常のJavaだけのビルドも可能ですが、その場合SPC実再生テストは明示的にスキップされます。
現在同梱するネイティブライブラリはWindows x64向けです。他OSのビルド・実再生は未検証です。
手動で起動する場合は `java --enable-native-access=ALL-UNNAMED ...` としてください。
開発時に独自のlibgmeを使う場合は `-Dmicropolis.gme.library=/path/to/library` を指定できます。
ライブラリがない・入力が壊れている場合はBGM設定画面に理由を表示し、ゲームは継続します。

JARの隣の `lib/` にデコーダーのJARが必要です。Mavenの `package` で `target/lib/` に配置します。
配布時にJARだけを移動せず、`lib/` とライセンス文書も一緒に置いてください。
ライブラリは個別JARのまま保持し、置き換えて利用できます。

## エラーと検証

設定なしの場合は無音です。設定や音楽が壊れている場合もゲームは継続し、BGM設定画面に理由を表示します。
DTD・外部実体参照・未知の設定項目は受け付けません。XMLから外部コマンドを実行しません。
再生・復号・ファイル読み込みはUIスレッドから分離し、音声全体をメモリに展開しません。

自動テストでは自作の440 Hz正弦波を4形式に変換した素材で復号結果が無音でないことを確認します。
XMLの異常、相対パス、ルールの競合、同じ曲の維持、割り込みからの復帰、一時停止、音量も検証します。

2026-11-02、Windows / Java 25で4形式の音声デバイス出力、ループ、フェード、
一時停止／再開、終了後の再生スレッド解放を確認しました。
音楽未設定での新規都市開始と、日本語のBGM設定画面の表示も確認しています。
音声は生成した正弦波による動作確認であり、楽曲ごとの音質を保証するものではありません。
SPCについても自作のSPC700プログラムと波形をテスト内で生成し、復号結果が無音でないことと反復解放を確認します。
手元のSPCでもPCM復号、音声デバイスへの出力、ループ、停止・再開、フェードと効果音の同時出力を確認しました。
この検証用音源は公開テスト・Git・配布ZIPには含めていません。
評価の支持率50%の境界、画面終了、祝賀と災害の優先順位、割り込み後の復帰、
新規都市への切り替え、追加場面の未定義時のフォールバックも自動テストで確認します。
追加曲は手元の2版から各7曲を確認し、デコードと音声デバイスへの出力を検証しました。
実際のBGMサービスでも評価・祝賀・災害・通常曲の切り替えと復帰、終了後の解放を確認しています。
